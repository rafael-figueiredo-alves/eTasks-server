Resumo Atual das Entidades do Banco

Data de referencia: 2026-04-08
Projeto fonte: eTasks-server.Models/Entities
Contexto de mapeamento: eTasks-server.Core/Data/AppDbContext.cs

Hoje o modelo persistido do sistema possui 18 entidades mapeadas no AppDbContext, cobrindo configuracao global, autenticacao, perfil, gamificacao, tarefas, metas, compras, anotacoes, leituras e financas.

O dominio continua centrado em User, que atua como owner dos recursos pessoais do aplicativo.

Blocos do Dominio

  • Configuracao global: eTasksVersion.
  • Identidade e autenticacao: User, RefreshToken, PasswordResetCode, LoginLog, UserSettings.
  • Gamificacao: BonusPointRule, UserBonusPoint, BonusAchievement, UserAchievement.
  • Tarefas e metas: TaskItem, TaskRecurrence, Goal.
  • Compras e conhecimento pessoal: ShoppingList, ShoppingListItem, NoteItem, ReadingItem.
  • Financas: FinanceEntry.

Entidades

eTasksVersion

Tabela: version
PK: Id
Natureza: configuracao singleton

Campos principais: Id, AppVersion, DisplayVersion, URL_APK, URL_Win.

User

Tabela: users
PK: Uid
Indice unico: Email

Owner principal do dominio pessoal. Relacionamentos: 1:N com RefreshToken, PasswordResetCode, LoginLog, UserBonusPoint, UserAchievement, TaskItem, Goal, ShoppingList, NoteItem, ReadingItem e FinanceEntry; 1:1 com UserSettings.

RefreshToken

Tabela: refresh_tokens
FK: UserUid -> User.Uid

Sessao renovavel de autenticacao com Token, UserAgent, ExpiresAt e IsRevoked.

PasswordResetCode

Tabela: password_reset_codes
FK: UserUid -> User.Uid

Token de recuperacao de senha com expiracao e uso unico.

LoginLog

Tabela: login_logs
Referencia opcional: UserUid -> User.Uid

Auditoria de tentativas de login com Status, IpAddress, UserAgent e CreatedAt.

UserSettings

Tabela: user_settings
FK unica: UserUid -> User.Uid

Preferencias 1:1 do usuario, com tema, idioma, tela inicial e opcoes do app.

BonusPointRule

Tabela: bonus_point_rules
Indice unico: Source

Catalogo central das regras padrao de pontuacao por origem.

UserBonusPoint

Tabela: user_bonus_points
FK: UserUid -> User.Uid

Ledger de pontos do usuario com Points, Source, Description, SourceReferenceId e CreatedAt.

BonusAchievement

Tabela: bonus_achievements
Indice unico: Code

Catalogo mestre de conquistas.

UserAchievement

Tabela: user_achievements
FKs: UserUid -> User.Uid e BonusAchievementId -> BonusAchievement.Id

Registro historico de conquistas adquiridas pelo usuario.

TaskItem

Tabela: task_items
FKs: UserUid -> User.Uid e GeneratedFromTaskId -> TaskItem.Id opcional

Tarefa concreta do usuario com Summary, Notes, Priority, TaskDate, IsCompleted e CompletedAt, simples ou gerada por recorrencia.

TaskRecurrence

Tabela: task_recurrences
FK unica: TaskItemId -> TaskItem.Id

Configuracao de recorrencia da tarefa base.

Goal

Tabela: goals
FK: UserUid -> User.Uid

Meta do usuario com Summary, Description, Type, Priority, RewardPoints, Status, CreatedAt e UpdatedAt.

ShoppingList

Tabela: shopping_lists
FK: UserUid -> User.Uid

Lista de compras com Name, Place, Type, TotalItems, TotalAmount e IsFinalized.

ShoppingListItem

Tabela: shopping_list_items
FK: ShoppingListId -> ShoppingList.Id

Itens da lista com Description, Unit, Quantity, UnitPrice, TotalAmount e IsCompleted.

NoteItem

Tabela: notes
FK: UserUid -> User.Uid

Anotacao livre do usuario com Subject, Content, CreatedAt e UpdatedAt, sem integracao direta com pontuacao.

ReadingItem

Tabela: reading_items
FK: UserUid -> User.Uid

Registro de leitura com Title, Authors, Subject, Summary, Opinion, Rating, TotalPages, CurrentPage, Genre, Format e Status.

FinanceEntry

Tabela: finance_entries
FK: UserUid -> User.Uid

Lancamento financeiro de entrada ou saida, recorrente ou nao, com EntryType, PaymentMethod, Amount, OccursOn, IsPaid e PaidAt.

Relacionamentos Consolidados

  • User 1:N RefreshToken, PasswordResetCode, LoginLog, UserBonusPoint, UserAchievement, TaskItem, Goal, ShoppingList, NoteItem, ReadingItem e FinanceEntry.
  • User 1:1 UserSettings.
  • BonusAchievement 1:N UserAchievement.
  • TaskItem 1:1 TaskRecurrence.
  • TaskItem 1:N TaskItem via GeneratedFromTaskId.
  • ShoppingList 1:N ShoppingListItem.
  • eTasksVersion e BonusPointRule nao dependem de outras entidades.
