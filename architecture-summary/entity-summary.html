Resumo Atual das Entidades do Banco

Data de referencia: 2026-04-05
Projeto fonte: eTasks-server.Models/Entities
Contexto de mapeamento: eTasks-server.Core/Data/AppDbContext.cs

Hoje o modelo persistido do sistema possui 9 entidades mapeadas no AppDbContext: eTasksVersion, User, RefreshToken, PasswordResetCode, LoginLog, UserSettings, UserBonusPoint, BonusAchievement e UserAchievement.

O dominio persistido e fortemente centrado em User, com tres blocos principais: autenticacao e ciclo de conta, configuracao/perfil do usuario e sistema de pontuacao/conquistas.

Leitura Arquitetural Rapida

  • Nucleo de identidade: User concentra identidade, credenciais, estado da conta e os principais relacionamentos.
  • Seguranca: RefreshToken, PasswordResetCode e LoginLog formam o bloco operacional de autenticacao.
  • Perfil: UserSettings modela preferencias 1:1 do usuario.
  • Gamificacao: UserBonusPoint, BonusAchievement e UserAchievement compoem o modulo de bonus.
  • Configuracao global: eTasksVersion funciona como singleton persistido de versao da aplicacao.

Entidades

eTasksVersion

Tabela: version
PK: Id
Natureza: configuracao singleton

Campos principais: Id, AppVersion, DisplayVersion, URL_APK, URL_Win.

Observacao: o sistema assume um unico registro; estruturalmente se comporta mais como configuracao persistida do que como agregado de negocio.

User

Tabela: users
PK: Uid
Indice unico: Email

Campos principais: identidade (Uid, Name, Email), autenticacao (PasswordHash), perfil (PhotoPath), acesso (IsConfirmed, IsAdmin, IsBlocked) e ciclo de vida (CreatedAt, LastAccessAt, IsDeleted, DeletedAt).

Relacionamentos: 1:N com RefreshToken, 1:N com PasswordResetCode, 1:1 com UserSettings, 1:N com UserBonusPoint e 1:N com UserAchievement.

Observacao estrutural: User concentra muitas responsabilidades e e o principal ponto de acoplamento do modelo atual.

RefreshToken

Tabela: refresh_tokens
PK: Id
FK: UserUid -> User.Uid

Representa sessao renovavel de autenticacao. Campos centrais: Token, UserAgent, ExpiresAt, IsRevoked, CreatedAt.

PasswordResetCode

Tabela: password_reset_codes
PK: Id
FK: UserUid -> User.Uid

Token de recuperacao de senha com expiracao e uso unico. Campos centrais: Code, ExpiresAt, IsUsed, CreatedAt.

LoginLog

Tabela: login_logs
PK: Id
Referencia opcional: UserUid -> User.Uid

Auditoria de login com Status, IpAddress, UserAgent e CreatedAt. Aceita UserUid nulo para tentativas sem usuario identificado.

Observacao: a navegacao existe, mas o relacionamento nao esta explicitamente configurado no OnModelCreating.

UserSettings

Tabela: user_settings
PK: Id
FK unica: UserUid -> User.Uid

Extensao 1:1 de preferencias do usuario. Campos centrais: Theme, Language, UseCamera, EnableBonusSystem, CreatedAt, UpdatedAt.

UserBonusPoint

Tabela: user_bonus_points
PK: Id
FK: UserUid -> User.Uid

Lancamento de pontos por usuario. Campos centrais: Points, Source, Description, CreatedAt.

Observacao: o saldo e derivado por soma, nao armazenado diretamente.

BonusAchievement

Tabela: bonus_achievements
PK: Id
Indice unico: Code

Catalogo mestre de conquistas. Campos centrais: Code, Name, Description, PointsRequired, IsActive, CreatedAt.

UserAchievement

Tabela: user_achievements
PK: Id
FKs: UserUid -> User.Uid e BonusAchievementId -> BonusAchievement.Id

Indice unico composto: (UserUid, BonusAchievementId)

Registro de conquista adquirida. Campos centrais: PointsAtAchievement e AchievedAt.

Observacao: preserva snapshot historico do contexto da conquista.

Pontos Estruturais Relevantes

  • User e o principal agregado do banco e concentra autenticacao, administracao, perfil e ganchos de gamificacao.
  • O bloco de autenticacao (RefreshToken, PasswordResetCode, LoginLog) ja e um candidato natural a modularizacao futura.
  • O bloco de bonus tambem ja tem uma fronteira util: catalogo (BonusAchievement) + lancamentos (UserBonusPoint) + historico de conquista (UserAchievement).
  • eTasksVersion parece mais configuracao singleton persistida do que entidade de negocio tradicional.
  • Vale explicitar no mapeamento a relacao de LoginLog com User se essa trilha de auditoria continuar relevante para o projeto.
